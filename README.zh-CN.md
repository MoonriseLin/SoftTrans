# Softdrop

[English](README.md) · **简体中文** · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

在网页里就能在你的设备之间传送文件和文字，比如从手机到电脑、从笔记本到平板。设备在同一个 Wi-Fi 下时，数据会通过局域网直接在设备之间传输。所有内容都是端到端加密的：服务器只负责让设备互相认识，永远看不到你发送的内容。

**马上试试：** 在两台设备上打开 **[https://mio.pantsu.uk](https://mio.pantsu.uk)**。

不需要安装任何东西。在 iPhone 或 Android 上，可以把页面添加到主屏幕，像应用一样使用（PWA）。界面支持英文、简体中文、繁體中文和日本語：默认跟随浏览器语言，在页面顶部选择的语言会被记住。

---

## 使用方法

1. 在两台设备上打开页面。如果它们连着同一个 Wi-Fi，一两秒内就会出现在对方的雷达上。
2. 点按要发送到的那台设备。
3. 输入或粘贴文字，或者拖入、选择文件，然后点按 **发送**。
4. 另一台设备会直接开始接收，不需要确认。两边都会显示已传大小和总大小（例如 `50.5 MB / 200.3 MB`）以及速度。
5. 每项传输都会标明它走的路线：
   - **直连 · 同一 Wi-Fi**：在局域网里设备直接互传。最快，服务器也不用承担任何流量。
   - **直连**：通过 NAT 穿透，跨越互联网在设备之间直接传输。
   - **经由中继**：经过服务器中继。只在无法直连时使用，依然是端到端加密。

**不在同一个网络的设备**（例如一部用移动数据的手机和家里的电脑）只需要配对一次：

1. 在其中一台设备上点按 **获取配对码**，屏幕上会出现一个 4 位数字，5 分钟内有效。
2. 在另一台设备上输入这个配对码，点按 **配对**。两台设备会立即完成配对。

之后只要两台设备都在线，不论在哪个网络，都能找到彼此。

## 设备之间是怎样工作的

```
 手机（浏览器 / PWA）                                     电脑（浏览器）
        │                                                        │
        │ 1. WebSocket（WSS）：注册、寻找设备、交换带签名的连接请求 │
        └───────────────────────►  服务器  ◄─────────────────────┘
                          信令 · STUN/TURN · 网页

        2. WebRTC 数据通道，端到端加密（DTLS）：
           a. 局域网直连 ............................ 优先
           b. 跨 NAT 直连（STUN）.................... 不同网络
           c. 经由 TURN 中继 ........................ 最后手段
```

### 1. 每台设备都有自己的身份

第一次打开时，浏览器会用 WebCrypto 生成一对 **ECDSA P-256 密钥**。私钥无法导出，只保存在浏览器的 IndexedDB 里。**设备 ID 就是公钥的 SHA-256 哈希值**。因为 ID 由密钥计算而来，别人无法冒用其他设备的 ID。每台设备还会得到一个随机的友好名称（比如 “Quiet Fox”），可以自己修改。

没有账号。身份以设备（浏览器）为单位。

### 2. 注册并发现附近的设备

页面会与服务器建立 WebSocket 连接。服务器发出一个随机挑战，设备用私钥签名作答。只有签名正确、并且 ID 与密钥相符时，服务器才会接受这台设备。

接着，服务器按照它看到的 **公网 IP 地址** 给设备分组（IPv6 按 /64 前缀分组）。同一个家用路由器后面的设备共享一个公网 IP，所以不需要任何设置，就会互相显示为 **附近** 的设备。在大型共享 NAT 后面（公司、校园、移动运营商），陌生人也可能被分到同一组。传输会自动接收，所以同组的任何人都能发给你。页面会一直显示附近有谁，以及每项传输来自谁。

**已配对的设备** 在任何网络下都能看到彼此。只有当 *双方* 都表示信任对方时，服务器才会让它们互相可见。这些信息只保存在内存里，不会写入磁盘。

### 3. 建立直连（信令）

浏览器之间要先交换连接信息，才能直接相连。这些信息就是 WebRTC 的 **offer**、**answer** 和 **ICE 候选地址**（可能可用的网络地址）。服务器负责转发这些消息，但无法伪造它们：

- 每条消息都用发送方的设备密钥 **签名**，接收方会先验证签名，再使用消息。
- offer 和 answer 里包含加密这条连接所用证书（DTLS）的指纹。指纹在签名范围内，等于被固定下来。连接建立后，双方还会再次核对实际使用的证书是否与它一致。

因此，无论是恶意的服务器，还是同一 Wi-Fi 里的其他人，都无法插到中间冒充你的设备。对于还没配对的设备，你需要信任服务器介绍的是正确的设备。配对会保存对方的公钥，之后的连接都会用这把公钥核对。配对本身依赖服务器和 4 位配对码，不需要再比对校验数字。

### 4. 选择传输路线

WebRTC 的 ICE 会同时尝试所有可能的路线，并保留可用的路线里最好的那一条：

| 路线 | 什么时候使用 | 标签 |
| --- | --- | --- |
| 局域网（host 对 host） | 在同一个 Wi-Fi，并且设备之间能互相访问 | 直连 · 同一 Wi-Fi |
| STUN（NAT 穿透） | 不同网络，且路由器允许穿透 | 直连 |
| 服务器上的 TURN 中继 | 严格的 NAT、开启了客户端隔离的访客 Wi-Fi、屏蔽 UDP 的网络 | 经由中继 |

标签来自浏览器实际选中的连接（`getStats()`），反映的是真实情况。走中继的设备在雷达上还会显示一圈虚线。中继使用服务器签发的限时凭据，只转发加密后的数据包，从不写入磁盘。

### 5. 发送文件

所有内容都经过一条可靠、有序的 **数据通道**：

1. 发送方先告知这项传输的名称、大小和类型。16 KB 以内的短文字会直接放在这条通知里。
2. 接收方自动接收，并准备好存储空间。
3. 文件以 **64 KB 的分块** 发送（如果对方浏览器不支持较大的消息，就用 16 KB）。发送时有背压控制，发得快也不会撑爆内存。接收方会回报进度，两边的进度圈和速度显示都以此为准。
4. 双方都会计算整个文件的 **SHA-256 哈希值**。只有两边一致时，接收方才会保留文件。
5. 浏览器支持时，收到的大文件会写进浏览器的私有存储（OPFS），否则以 Blob 形式保存。之后点按 **保存**，在手机上也可以点按 **分享**。

任何一方都可以取消。如果传到一半连接断了（例如手机锁屏、Wi-Fi 切换），传输会暂停，等设备重新连上后从中断的位置继续。

### 服务器能看到什么、看不到什么

| 服务器知道 | 服务器永远看不到 |
| --- | --- |
| 在线设备的 ID、名称、设备类型和公网 IP | 你发送的文件内容或文字 |
| 在线期间，哪些设备彼此配对 | 文件名和大小（它们在加密通道里传输） |
| 有连接建立；使用 TURN 时中继的字节数 | 你的私钥 |

没有账号，没有追踪，也没有数据统计。

## 注意事项

- **在手机上请保持页面开启。** iOS 和 Android 会暂停在后台的网页，传输也会一起暂停。传输期间，页面会在浏览器允许的情况下保持屏幕常亮。
- **访客 Wi-Fi 和公共 Wi-Fi** 常常会阻止设备之间互相通信（客户端隔离）。这时传输会经由中继，能用但会比较慢。
- **在 iPhone 上传送超大文件** 时，可能会碰到 Safari 的内存限制。
- 在同一个浏览器的第二个标签页打开 Softdrop，设备会转移到最新的那个标签页。
- 在网址后面加上 `?relay=1` 可以强制走中继，方便测试。
- **调试日志**：页面会记录连接和传输的每一步，并发送到服务器日志。日志窗口默认隐藏，在网址后面加上 `?debug=1` 可以显示。用 `?debug=0` 停止记录。在服务器上用 `sh deploy/logs.sh` 查看日志。

## 开发者

```
server/      信令服务器（Node 20 + ws）：在线状态、IP 分组、配对码、带签名的信令转发、TURN 凭据
web/         应用本体，不需要构建：index.html、app.css、js/*.js、Service Worker、manifest、图标
  js/identity.js   设备密钥、受信任的设备
  js/signaling.js  WebSocket 客户端
  js/rtc.js        WebRTC 连接、签名验证、DTLS 固定、路线判断
  js/transfer.js   传输协议（meta/accept/分块/哈希/取消/续传）
  js/sinks.js      收到的数据存放在哪里（OPFS 或 Blob）
  js/i18n.js       英文、简体中文、繁體中文、日本語
e2e/         双浏览器端到端测试（Playwright）
deploy/      nginx 站点、systemd 服务、coturn 配置、安装脚本
prototype/   最初的前端原型（视觉参考）
docs/        设计方案、协议（见 “As built”）、部署说明
```

**本地运行**

```sh
cd server && npm install && npm start    # http://127.0.0.1:8480
npm test                                 # 单元测试
```

在同一台电脑上用两个浏览器配置文件（比如一个普通窗口和一个无痕窗口），它们会互相显示为附近的设备。如果没有设置 `TURN_HOST` 和 `TURN_SECRET`，就只能走直连。

**端到端测试**

```sh
cd e2e && npm install && npx playwright-core install chromium-headless-shell
node run.mjs                                       # 针对本地服务器
BASE=https://mio.pantsu.uk node run.mjs       # 针对线上环境
QUERY='?relay=1' WANT_ROUTE=relay WANT_LABEL='Via relay' BASE=https://mio.pantsu.uk node run.mjs
```

**部署（在 VPS 上）：** `sh deploy/install.sh`。nginx、coturn 和证书的说明见 [docs/deploy-notes.md](docs/deploy-notes.md)，消息格式见 [docs/protocol-draft.md](docs/protocol-draft.md)（英文）。
