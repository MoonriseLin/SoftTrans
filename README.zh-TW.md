# Softdrop

[English](README.md) · [简体中文](README.zh-CN.md) · **繁體中文** · [日本語](README.ja.md)

在網頁裡就能在你的裝置之間傳送檔案和文字，例如從手機到電腦、從筆電到平板。裝置在同一個 Wi-Fi 時，資料會透過區域網路直接在裝置之間傳輸。所有內容都是端對端加密：伺服器只負責讓裝置互相認識，永遠看不到你傳送的內容。

**馬上試試：** 在兩台裝置上開啟 **[https://mio.pantsu.uk](https://mio.pantsu.uk)**。

不需要安裝任何東西。在 iPhone 或 Android 上，可以把頁面加入主畫面，像 App 一樣使用（PWA）。介面支援英文、简体中文、繁體中文和日本語：預設跟隨瀏覽器語言，在頁面上方選擇的語言會被記住。

---

## 使用方式

1. 在兩台裝置上開啟頁面。如果它們連著同一個 Wi-Fi，一兩秒內就會出現在對方的雷達上。
2. 點按要傳送到的那台裝置。
3. 輸入或貼上文字，或者拖入、選擇檔案，然後點按 **傳送**。
4. 另一台裝置會顯示這筆傳輸，以及 **接收** 和 **拒絕** 按鈕。對方接收之前，什麼都不會儲存。
5. 每筆傳輸都會標示它走的路線：
   - **直連 · 同一個 Wi-Fi**：在區域網路裡裝置直接互傳。最快，伺服器也不用負擔任何流量。
   - **直連**：透過 NAT 穿透，跨越網際網路在裝置之間直接傳輸。
   - **經由中繼**：經過伺服器中繼。只在無法直連時使用，依然是端對端加密。

**不在同一個網路的裝置**（例如一支用行動網路的手機和家裡的電腦）只需要配對一次：

1. 在其中一台裝置上點按 **取得配對碼**，畫面上會出現一組 6 位數字，5 分鐘內有效。
2. 在另一台裝置上輸入這組配對碼，點按 **配對**。
3. 兩邊螢幕都會顯示同一組 6 位驗證數字。確認一致後點按 **一樣**。

之後只要兩台裝置都在線上，不論在哪個網路，都能找到彼此。

## 裝置之間是怎麼運作的

```
 手機（瀏覽器 / PWA）                                     電腦（瀏覽器）
        │                                                        │
        │ 1. WebSocket（WSS）：註冊、尋找裝置、交換附簽章的連線請求 │
        └───────────────────────►  伺服器  ◄─────────────────────┘
                          信令 · STUN/TURN · 網頁

        2. WebRTC 資料通道，端對端加密（DTLS）：
           a. 區域網路直連 .......................... 優先
           b. 跨 NAT 直連（STUN）.................... 不同網路
           c. 經由 TURN 中繼 ........................ 最後手段
```

### 1. 每台裝置都有自己的身分

第一次開啟時，瀏覽器會用 WebCrypto 產生一組 **ECDSA P-256 金鑰**。私鑰無法匯出，只保存在瀏覽器的 IndexedDB 裡。**裝置 ID 就是公鑰的 SHA-256 雜湊值**。因為 ID 由金鑰計算而來，別人無法冒用其他裝置的 ID。每台裝置還會得到一個隨機的友善名稱（例如「Quiet Fox」），可以自行修改。

沒有帳號。身分以裝置（瀏覽器）為單位。

### 2. 註冊並發現附近的裝置

頁面會和伺服器建立 WebSocket 連線。伺服器送出一個隨機挑戰，裝置用私鑰簽章回應。只有簽章正確、而且 ID 和金鑰相符時，伺服器才會接受這台裝置。

接著，伺服器依照它看到的 **公開 IP 位址** 替裝置分組（IPv6 依 /64 前綴分組）。同一台家用路由器後面的裝置共用一個公開 IP，所以不需要任何設定，就會互相顯示為 **附近** 的裝置。在大型共用 NAT 後面（公司、校園、電信業者），陌生人也可能被分到同一組。所以接收方每次都必須自己確認接收。

**已配對的裝置** 在任何網路下都能看到彼此。只有當 *雙方* 都表示信任對方時，伺服器才會讓它們互相可見。這些資訊只保存在記憶體裡，不會寫入磁碟。

### 3. 建立直連（信令）

瀏覽器之間要先交換連線資訊，才能直接相連。這些資訊就是 WebRTC 的 **offer**、**answer** 和 **ICE 候選位址**（可能可用的網路位址）。伺服器負責轉送這些訊息，但無法偽造它們：

- 每則訊息都用傳送方的裝置金鑰 **簽章**，接收方會先驗證簽章，再使用訊息。
- offer 和 answer 裡包含加密這條連線所用憑證（DTLS）的指紋。指紋在簽章範圍內，等於被固定下來。連線建立後，雙方還會再次核對實際使用的憑證是否和它一致。

因此，無論是惡意的伺服器，還是同一個 Wi-Fi 裡的其他人，都無法插到中間冒充你的裝置。對於還沒配對的裝置，你需要信任伺服器介紹的是正確的裝置。配對可以去掉這一層信任：雙方會比對一組由兩邊公鑰計算出的簡短驗證數字。

### 4. 選擇傳輸路線

WebRTC 的 ICE 會同時嘗試所有可能的路線，並保留可用路線裡最好的那一條：

| 路線 | 什麼時候使用 | 標籤 |
| --- | --- | --- |
| 區域網路（host 對 host） | 在同一個 Wi-Fi，而且裝置之間能互相連到 | 直連 · 同一個 Wi-Fi |
| STUN（NAT 穿透） | 不同網路，且路由器允許穿透 | 直連 |
| 伺服器上的 TURN 中繼 | 嚴格的 NAT、開啟用戶端隔離的訪客 Wi-Fi、封鎖 UDP 的網路 | 經由中繼 |

標籤來自瀏覽器實際選中的連線（`getStats()`），反映的是真實情況。走中繼的裝置在雷達上還會顯示一圈虛線。中繼使用伺服器核發的限時憑證，只轉送加密後的封包，從不寫入磁碟。

### 5. 傳送檔案

所有內容都經過一條可靠、有序的 **資料通道**：

1. 傳送方先告知這筆傳輸的名稱、大小和類型。16 KB 以內的短文字會直接放在這則通知裡。
2. 接收方選擇 **接收** 或 **拒絕**。
3. 檔案以 **64 KB 的區塊** 傳送（如果對方瀏覽器不支援較大的訊息，就用 16 KB）。傳送時有背壓控制，傳得快也不會塞爆記憶體。接收方會回報進度，兩邊的進度圈和速度顯示都以此為準。
4. 雙方都會計算整個檔案的 **SHA-256 雜湊值**。只有兩邊一致時，接收方才會保留檔案。
5. 瀏覽器支援時，收到的大檔案會寫進瀏覽器的私有儲存空間（OPFS），否則以 Blob 形式保存。之後點按 **儲存**，在手機上也可以點按 **分享**。

任何一方都可以取消。如果傳到一半連線中斷（例如手機鎖定螢幕、Wi-Fi 切換），傳輸會暫停，等裝置重新連上後從中斷的地方繼續。

### 伺服器看得到什麼、看不到什麼

| 伺服器知道 | 伺服器永遠看不到 |
| --- | --- |
| 線上裝置的 ID、名稱、裝置類型和公開 IP | 你傳送的檔案內容或文字 |
| 在線上期間，哪些裝置彼此配對 | 檔案名稱和大小（它們在加密通道裡傳輸） |
| 有連線建立；使用 TURN 時中繼的位元組數 | 你的私鑰 |

沒有帳號，沒有追蹤，也沒有數據分析。

## 注意事項

- **在手機上請保持頁面開啟。** iOS 和 Android 會暫停在背景的網頁，傳輸也會一起暫停。傳輸期間，頁面會在瀏覽器允許的情況下讓螢幕保持亮著。
- **訪客 Wi-Fi 和公共 Wi-Fi** 常常會阻擋裝置之間互相通訊（用戶端隔離）。這時傳輸會經由中繼，能用但會比較慢。
- **在 iPhone 上傳送超大檔案** 時，可能會碰到 Safari 的記憶體限制。
- 在同一個瀏覽器的第二個分頁開啟 Softdrop，裝置會轉移到最新的那個分頁。
- 在網址後面加上 `?relay=1` 可以強制走中繼，方便測試。

## 開發者

```
server/      信令伺服器（Node 20 + ws）：上線狀態、IP 分組、配對碼、附簽章的信令轉送、TURN 憑證
web/         應用本體，不需要建置：index.html、app.css、js/*.js、Service Worker、manifest、圖示
  js/identity.js   裝置金鑰、受信任的裝置、配對驗證數字
  js/signaling.js  WebSocket 用戶端
  js/rtc.js        WebRTC 連線、簽章驗證、DTLS 固定、路線判斷
  js/transfer.js   傳輸協定（meta/accept/區塊/雜湊/取消/續傳）
  js/sinks.js      收到的資料存放在哪裡（OPFS 或 Blob）
  js/i18n.js       英文、简体中文、繁體中文、日本語
e2e/         雙瀏覽器端對端測試（Playwright）
deploy/      nginx 網站、systemd 服務、coturn 設定、安裝腳本
prototype/   最初的前端原型（視覺參考）
docs/        設計方案、協定（見「As built」）、部署說明
```

**本機執行**

```sh
cd server && npm install && npm start    # http://127.0.0.1:8480
npm test                                 # 單元測試
```

在同一台電腦上用兩個瀏覽器設定檔（例如一個一般視窗和一個無痕視窗），它們會互相顯示為附近的裝置。如果沒有設定 `TURN_HOST` 和 `TURN_SECRET`，就只能走直連。

**端對端測試**

```sh
cd e2e && npm install && npx playwright-core install chromium-headless-shell
node run.mjs                                       # 針對本機伺服器
BASE=https://mio.pantsu.uk node run.mjs       # 針對正式環境
QUERY='?relay=1' WANT_ROUTE=relay WANT_LABEL='Via relay' BASE=https://mio.pantsu.uk node run.mjs
```

**部署（在 VPS 上）：** `sh deploy/install.sh`。nginx、coturn 和憑證的說明見 [docs/deploy-notes.md](docs/deploy-notes.md)，訊息格式見 [docs/protocol-draft.md](docs/protocol-draft.md)（英文）。
